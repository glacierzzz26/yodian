## 交付物

`merchant-web/`（Vue3 + Vite + TS + Pinia + antdv）可运行脚手架：登录 + 应用外壳 + 三角色路由与菜单守卫 + mock 数据层（信封契约占位）。后续 1.2/1.3 的页面以「路由 key → 视图文件」显式映射的方式叠加在本脚手架上。

| 项 | 内容 |
|---|---|
| 工程骨架 | Vite + Vue3 `<script setup>` + TS + Pinia + vue-router；axios（`src/api/http.ts`，统一 `{code,msg,data}` 解包 + Bearer token） |
| 登录 | `views/Login.vue`：工号 + 密码，三角色（owner/cashier/kitchen）；开发态预填 1001/123456 + 角色快捷选择；登录态存 Pinia `stores/auth.ts` |
| 应用外壳 | `layouts/MainLayout.vue` + `router/menu.ts` 侧边栏分组（5 组，与 `商家端原型.html` 导航一致），按 16.2 权限矩阵标注角色 |
| 角色路由 | `router/index.ts`：`ROUTE_ROLES` 页面→角色矩阵 + `beforeEach` 守卫（未登录→/login 带 redirect；无权限→重定向该角色首页 `firstPath`）；`/kds` 独立全屏暗色路由（不带外壳） |
| mock 数据层 | `api/mock.ts`：全站数据占位（悦点 1 店 / 18 菜 / 桌台区域 / 员工 / 信封返回），契约字段与 7.4/16.1 一致，供 1.2/1.3 页面消费；后端就绪后切真实 API（阶段 4） |
| 类型 | `types/index.ts`：Role/Order/Table 等共享 TS 类型 |

> 说明：本仓库为初始入库（无更早 git 历史），本归档按脚手架当前交付形态描述，不区分 1.1 阶段结束时与现状的增量差异（页面视图由 1.2/1.3 通过 `VIEW_MAP` 叠加）。

## 验收证据

1. `pnpm dev` 启动 Vite 开发服务，`/login` 可达。
2. 三角色登录成功（owner→/dashboard；cashier→/dashboard；kitchen→/kds），登录态持久于 Pinia + localStorage。
3. 未登录访问受保护路由 → 重定向 `/login?redirect=...`；登录后回跳原目标。
4. cashier 访问 owner-only 路由（如 `/menu`）→ 重定向 `/dashboard`（路由守卫生效）。
5. `/kds` 全屏暗色，无商家端外壳。
6. mock 层返回统一信封 `{code,msg,data}`，页面消费字段与设计方案接口契约一致。

## 关键实现决策

- **路由 key ≠ 视图文件名**：`VIEW_MAP` 显式映射，页面命名可自由描述（如 `table map` → `TableMap.vue`），后续新增页面只加映射不改路由结构。
- **角色矩阵单一来源**：`ROUTE_ROLES` 与 `menu.ts` 的 `roles` 同源语义（16.2 权限矩阵），守卫与菜单可见性不双写。
- **KDS 独立路由**：不挂在 MainLayout 下，保证后厨大屏全屏暗色、无导航干扰（10.2）。
- **数据层双轨**：mock 先占位、`http.ts` 真实层就绪但未接线——阶段 4 联调时逐页替换（doc-driven 契约方法论：前端按 16 章接口契约消费信封，接口形状不因 mock 走样）。
