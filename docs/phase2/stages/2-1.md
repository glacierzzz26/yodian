## 交付物

`server/` Go 后端工程骨架，可启动、可迁移、可健康检查。业务契约对应设计方案 7.1/8/16 章。

| 项 | 内容 |
|---|---|
| 工程 | `github.com/yodian/server`，Gin + GORM + golang-migrate 风格 SQL + go-redis + godotenv |
| 配置 | `.env.example` 覆盖设计 8 章全部变量（含 `MOCK_*`/`ENABLE_*` 正交开关）；`config.Load()` 缺省可跑 dev |
| 迁移 | `migrations/*.up/down.sql`，`store.MigrateUp` 启动时自动执行，`schema_migrations` 记版本，事务内执行、失败回滚、重启幂等 |
| 表结构 | 7.1 全部 15 表逐字落地（含部分唯一索引/CHECK/COMMENT）+ `employees` 补充表 + `schema_migrations` = 17 表 |
| seed | `0002_seed`：悦点 1 店 + 6 分类 + 18 菜（id 显式 1-18 与前端 mock 对齐）+ 3 区域 + 24 桌 + 按人项 2 条 + 员工 3 名 |
| 包络 | `pkg/respond`：`{code,msg,data}` + 错误码常量（1-5 万段区间，16.1） |
| 金额 | `model.Money`（int64 分）自定义 GORM 类型：入库 `NUMERIC(10,2)` 元、出库转分，禁止 float 参与计算 |
| 服务 | `cmd/server/main.go`：配置→DB→Redis→迁移→路由→监听；`/api/health` 检查 db/redis；`NoRoute` 统一 404 信封 |
| 本地环境 | `deploy/docker-compose.dev.yml`：PG16 + Redis7（healthcheck + 持久卷）；Makefile |

## 设计缺口修正（对照现状发现，已定稿）

1. **employees 表**：设计文档 7.1 无员工表，但 16.2 要求员工 JWT、前端 Staff 契约要员工管理 → 阶段 2 补齐 `employees`（shop_id/name/employee_no/password_hash/role/phone/status/last_login_at，UNIQUE(shop_id, employee_no)）。已在 `phase2/design/README.md` 记录。
2. **下架 vs 沽清映射**：前端 mock 的 `status:'off'`（下架）与 `soldOut`（沽清）在后端只有 `dishes.is_sold_out` 一个字段 → MVP 统一映射 `is_sold_out=true`（不可售、顾客端不可见）。seed 里夫妻肺片（前端 off）与佛跳墙（前端 soldOut）均落 `is_sold_out=true`；两种 tag 的区分在阶段 4 前端切换时收口。
3. **路由前缀修正**：按 7.4 接口表 `/api` + 单层业务前缀（16.2 示例的双 admin 前缀为文档笔误）。

## 验收证据

- `go build ./...` / `go vet ./...` 通过，`bin/server` 构建成功。

## 已知取舍 / 下一步

- GORM 只作 CRUD 模型，不做 AutoMigrate（迁移以 SQL 为准，可逆 down 文件齐全）。
- gin 默认 debug 模式 + 信任所有代理的警告：阶段 4 生产化时 `GIN_MODE=release` + `SetTrustedProxies`。
- 员工密码 seed 统一 `123456`（bcrypt cost 10），登录实现（2.4）时校验「首登强制修改」预留。
- 下一步：**阶段 2.2 核心交易闭环**——顾客登录（mock code）、菜单（签名+沽清）、下单（服务端算金额）、Mock 支付网关 + 回调幂等、prepay 状态机。
