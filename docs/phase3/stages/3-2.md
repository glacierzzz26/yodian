# 阶段 3.2 · 中间页 H5 一码双扫

> 归档日期：2026-08-25 ｜ 阶段：✅ 完成
> 续接依据：本归档 + `进度总表.md` + `phase3/design/README.md`；不靠对话记忆。

## 交付物

`landing/index.html` 单文件兜底页（设计 4.3）+ server `go:embed` 挂根路径 `/t`（非 /api）。

| 项 | 内容 |
|---|---|
| 载体 | `landing/` 独立小模块（module `github.com/yodian/landing`），`landing.go` `//go:embed index.html`；server `go.mod` 以 `replace github.com/yodian/landing => ../landing` 引用，构建时嵌入二进制 |
| 挂载 | `router.go` `r.GET("/t")` + `r.GET("/t/")` → `text/html` 返回；`QR_BASE_URL`（默认 `http://localhost:8080/t`）即指向此页 |
| 极轻 | 单文件、无框架、内联样式、零外部请求（3556B）；无表单/无 fetch/无 input，**不暴露任何点单能力** |
| 扫码参数 | 按契约 #5 解析 `?tid=&sig=`（无 ts；qr_version 承担吊销），微信 `scene` / 支付宝 `query` 均映射此形态 |

## 页面三分支（4.3）

| 分支 | 判定 | 文案 |
|---|---|---|
| 签名缺失 | `!tid \|\| !sig` | 「二维码无效」+ 请联系服务员（场景 3；H5 无 secret 不本地验签，真校验在小程序入口页调 `/tables/:tid/menu`，见 5.4 差异） |
| 微信 | `/MicroMessenger/` | 「正在进入小程序」+ 引导重扫/右上角菜单（场景 1：平台规则未生效/灰度） |
| 支付宝 | `/AlipayClient|TinyAppHelper/` | 「正在进入小程序」+ 引导重扫（场景 1） |
| 其他 | 默认 | 「请使用微信或支付宝扫码」+ 明确提示本页不提供点单功能（场景 2） |

## 关键实现决策

- **嵌入位置用 replace 子模块而非 server/static 副本**：Go `//go:embed` 禁止 `../` 越出包目录，而 `server/` 是仓库内唯一 Go 模块、设计树把 `landing/index.html` 放在仓库根 → 若复制进 server 会有双份漂移风险。故将 `landing/` 建为独立小模块（无第三方依赖），server 以 `replace` 引用；**唯一源码 + 零构建步骤 + 嵌入进二进制**，设计树路径保持不变。
- **H5 不做本地验签**：secret 不下发（5.4 差异），H5 只按「有无 sig」给兜底文案；真正校验/进入菜单由小程序入口页完成。
- **非双平台环境不暴露点单能力**：场景 2 页面无任何表单/接口调用，仅引导文案（4.3 要求，防在浏览器误操作）。
- 页面需保持极轻（预算 ≤400ms）：未引入任何 CSS 框架/图标库/字体请求，CSS+JS 全部内联且 JS 无网络 IO。

## 验收证据（curl 冒烟）

```
GET /t                → 200 text/html 3556B
GET /t（无参数）        → 「二维码无效」（无 sig 兜底）
GET /t?tid=11&sig=abc  → 「请使用微信或支付宝扫码」（其他环境提示）
GET /t?tid=11&sig=abc + MicroMessenger UA → 「正在进入小程序」（微信引导）
GET /t?tid=11&sig=abc + AlipayClient UA   → 「正在进入小程序」（支付宝引导）
GET /t/               → 200（尾斜杠兼容）
页面内 form/fetch/input 引用计数 = 0（不暴露点单能力）
QR_BASE_URL=http://localhost:8080/t 命中本页 ✓
```
