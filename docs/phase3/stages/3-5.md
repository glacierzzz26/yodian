## 关键实现决策

- **结账预览不加锁，发起才锁**：`GET /bill/preview` 只读聚合（不锁会话，可继续加菜）；`POST /bill` 才置 `LockedForBill` 防并发——收银台页面停留期间同桌仍可加菜。
- **待支付结账单可取消重发**：会话被锁/已有待付 bill（20004/20010）→ 明确提示「取消结账并重新发起」→ `POST /bill/cancel` 解锁重来；对应 3.7 超时未付、9.8 取消支付后重新结账。
- **收银台统一处理 order/bill 两态**：查单定终态（弱网补单 9.8）→ prepay（order 按 `order_id`、bill 按 `bill_id`）→ mock/真实渠道分支共用 → 按模式分别轮询订单终态 / 会话 settled。`pollSessionSettled` 由服务端终态驱动，天然幂等。
- **换渠道不重开收银台**：`/pay/switch` 复用原 `order_id`，前端仅换 `out_trade_no`/`params`/`payChannel`，重新显示待付金额；`isMock` 由新 params 判定，切到真实渠道分支时调起 SDK（阶段 4）。
- **会话门控**：订单/结账/呼叫均以 `session.sid` 为前置（下单后才解锁），避免「无会话空页」；入口页直达路径（非扫码）也能用——有 tid/sig 则补拉菜单。
- **呼叫限频**：服务端 10s/顾客 1 次（`RateLimitBy`），冒烟中 42900 即该限频的正常拦截（非缺陷）。
