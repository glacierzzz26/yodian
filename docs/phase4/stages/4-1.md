## 关键实现决策

- **读端点全部返回金额分、适配层折元**：后端与契约 7.4 一致用 int64 分；前端视图的 `¥{{ x.toFixed(2) }}` 不变，换算集中在 `mock.ts` 适配层，视图零改动。
- **代客收款补小端点而非复用会话级 bill/pay**：先付单是「单订单即时收款」（现金/POS/扫码），会话级 `bill/pay` 只服务后付统一结账——两态并存（3.7）。
- **后厨写状态走专用 KDS 端点而非收银台端点**：权限矩阵（16.2）后厨「接单/出餐」≠ 收银「改状态」；7.4 §1982 的 `kitchen.POST /kds/:id/move` 在 2.4 未实现，联调「后厨也走 `/orders/:id/status`」测试暴露此缺口。修复：新增 `/kds/:id/move`（kitchen|owner），后厨访问 `/orders/:id/status` 保持 40003。前端 Kds.vue 按 `auth.role` 分流。
- **敏感操作审计留痕补齐**：16.2 要求结账/退款/核销/清台/沽清/代客收款留痕 `audit_logs`；2.4 的 `session.close`/`write_off`/`order.refund` handler 漏调 `RecordAudit`（联调测试断言 `session.close` 落库失败暴露）。修复：三处 handler + 新 `KdsMove` 全部补 `RecordAudit`（动作 `session.close`/`session.write_off`/`order.refund`/`order.kds_move`）。
- **后付单 KDS 无后端状态**：状态机（7.2 B）`unsettled→paid→done` 无 `preparing/served`；KDS 对后付单的「开始制作/完成出餐」仅本地标记（不写后端），先付单才 `changeOrderStatus`。这是诚实取舍，不是缺陷。
- **Pos 外带（TID=0）后端不支持**：`createOrder` 需有效桌台（`db.First(&t, ...)`），Pos 外带场景弹提示「后端未支持」，联调覆盖桌台代客点单。
- **按人项由服务端按 pax 自动计入**：`/admin/dishes` 不返回 per_head 菜品；Pos 清单不再带 per_head 行，改由 `pax` 触发后端自动加餐位费等（3.8），Pos `pax` 取清单内 per_head 数量或默认 2。
- **对账六口径由 ReconSnapshot 转换**：`order_receivable+bill_receivable`=订单口径、`payment_by_channel` 分渠道=网关/渠道口径、现金/POS/扫码=收银口径、退款/净额=财务口径、挂账/核销单独列示、`diff`（应收-实收）做校验行——视图的 `diffCount/totalDiff` 语义自动对上。

### 关键实现决策

- **P0-1 根因订正（重要）**：评审称「消费 JWT 的 `SID` 即可修复 IDOR」**有误**——顾客 JWT 的 `SID` 是 **`shop_id`**（设计 16.2 `{cid, ch, sid:shop_id, exp}`），非会话 id，消费它不能判定会话归属。正确修法是**成员断言**（`table_session_members`）：归属 = 顾客是会话成员。此方案同时是 P1-3 拼桌互见的前提（B 扫码即成员，无须先下单）。
- **非成员与会话不存在共用一个错误码**：避免「403=存在但不属于我 / 20008=不存在」构成 sid 枚举预言机。
- **成员两条写入路径统一**：下单事务内 `addSessionMember`；扫码 `POST /tables/:tid/join`。`join` 对无 active 会话的桌返回 `session_id=null`（尚未开台），客户端仍可点单。
- **P0-2 不破坏现有前端**：已查 `merchant-web` 仅发 `preparing`/`served`（Kds.vue），新增的后厨/收银可达状态收紧不影响现有调用。
- **`POST /tables/:tid/join` 为契约补充**：7.4 接口表未列，与 3.1 的 `bill/cancel` 同口径记入本归档。
- **miniprogram 类型层放宽**：`@dcloudio/types` 的 `RequestOptions.method` 联合缺 `PATCH`（运行时支持），`utils/request.ts` 放宽并在此处收敛转型——不新增类型错误。
